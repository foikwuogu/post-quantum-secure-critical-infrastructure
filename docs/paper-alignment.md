# Alignment with the 2024 Paper

Source:

**Ogochukwu Friday Ikwuogu et al., "Quantum-Resilient Infrastructure: Migrating US Financial Payment System to Post-Quantum Cryptography (PQC) Standards to Prevent 'Harvest Now, Decrypt Later' Attacks," IJCATR, Volume 13, Issue 12, 198–213, 2024, DOI 10.7753/IJCATR1312.1016.**

## Section-level mapping

### Threat model

The paper emphasizes the quantum threat to classical public-key infrastructure and the HNDL strategy. The project represents this through an asset inventory, secrecy lifetime, migration duration, criticality, and a transparent quantum-risk model.

### NIST PQC standards

The paper discusses ML-KEM/Kyber and ML-DSA/Dilithium. The implementation uses their **final NIST names**:

- ML-KEM-768 — FIPS 203
- ML-DSA-65 — FIPS 204

SLH-DSA is documented as a future/root-of-trust extension point because the paper discusses it as an alternative signature family.

### Hybrid key exchange

The paper proposes combining a classical ECDH secret with an ML-KEM secret and deriving a symmetric key from both.

This project implements:

```text
X25519 shared secret
        +
ML-KEM-768 shared secret
        |
        v
HKDF-SHA-256
        |
        v
AES-256-GCM key
```

### Dual signatures

The paper proposes dual/composite signatures for migration compatibility.

This project implements:

```text
Ed25519 signature
        +
ML-DSA-65 signature
        |
        v
Hybrid verification
```

Strict hybrid verification requires both signatures to validate.

### Performance

The paper emphasizes key/signature size, packet expansion, latency, throughput and hardware constraints. The project measures actual local encryption/signing time and envelope size.

The project does not reproduce or claim the paper's numeric performance values. Local measurements are generated by the user's own environment.

### Cryptographic agility

The paper calls for cryptographic agility. This project separates application logic from algorithm profiles so that the cryptographic mode can be changed without rewriting the message-processing layer.

## Domain adaptation

The paper's primary domain is U.S. financial payment infrastructure.

This project adapts the same technical migration pattern to a synthetic **critical-energy IT/OT environment**, because that domain is directly relevant to the broader critical-infrastructure cybersecurity endeavor.

This is an engineering extension, not a claim that the paper studied energy infrastructure.
